## Этап 0 — вернуть проект в собираемое состояние

Цель этапа: **свежий клон запускается без ошибок, а собранный APK показывает мир.**
Сейчас не выполняется ни одно из двух. Все правки этапа мелкие и изолированные —
ни одна не трогает игровую логику.

### 0.1. Убрать автозагрузку `McpBridge` (ревью 2.1)

Файл: `project.godot`.

Удалить строку:

```ini
McpBridge="*res://mcp_bridge.gd"
```

Заодно убрать `mcp_bridge.gd` и `/mcp_bridge.gd.uid` из `.gitignore` — они больше
ни на что не ссылаются.

Ссылку уже удаляли дважды (`fc581f2`, `6741401`), и она возвращалась. Чтобы это не
повторилось в третий раз, dev-мост стоит оформить как редакторский плагин:
`addons/mcp_bridge/plugin.cfg` + `EditorPlugin`. Плагины включаются через
`[editor_plugins] enabled=`, а не через `[autoload]`, и не попадают в игровую сборку
вообще. Тогда локальный инструмент физически не сможет сломать чужой запуск.

**Критерий приёмки:** `godot --headless --quit-after 60` не выводит ни одного `ERROR`.

### 0.2. Перевести загрузку мира на ресурсы вместо `Image.load()` (ревью 2.2)

Файл: `scripts/levels/level_01.gd`, функции `_add_map_sprite()` и `_add_lifts()`.

Это самая важная правка плана: она превращает собранную игру из пустого экрана в игру.

```gdscript
func _add_map_sprite(node_name: String, path: String, z: int) -> void:
	if not ResourceLoader.exists(path):
		push_error("Missing world texture %s" % path)
		return
	var sprite := Sprite2D.new()
	sprite.name = node_name
	sprite.centered = false
	sprite.texture_filter = CanvasItem.TEXTURE_FILTER_NEAREST
	sprite.scale = Vector2(_scale, _scale)
	sprite.z_index = z
	sprite.texture = load(path)
	add_child(sprite)
	move_child(sprite, 0)
```

Три момента, каждый из которых важен сам по себе:

1. `load()` вместо `Image.load()` + `ImageTexture.create_from_image()`. `load()` читает
   импортированный `.ctex`, который в `.pck` есть.
2. `ResourceLoader.exists()` вместо `FileAccess.file_exists()`. Второй проверяет наличие
   файла на диске и в пакете всегда возвращает `false`.
3. **Обязательно `push_error()` вместо тихого `return`.** Сейчас отказ ничем себя не
   выдаёт — именно поэтому баг дожил до сегодняшнего дня. Молчаливый выход из функции,
   загружающей обязательный ресурс, недопустим.

Ту же правку применить к загрузке `s2_lift.png` в `_add_lifts()` (там сейчас
`Image.load()` внутри `if FileAccess.file_exists(...)`).

**Важное следствие, которое нужно учесть сразу.** После перехода на `load()` к текстурам
начнут применяться настройки импорта — и тут возникает развилка, потому что обе ветки
плохи:

- VRAM-сжатие включено (`import_etc2_astc=true` в `project.godot`) — ETC2/ASTC
  блочно-компрессионные и **с потерями**. На двухцветной ZX-графике с жёсткими границами
  это даёт видимый мусор по краям каждого символа.
- VRAM-сжатие выключено (`Lossless`) — картинка чистая, но это 288 МБ в видеопамяти
  (см. 1.1).

Поэтому 0.2 нужно рассматривать как исправление корректности, а не как окончательное
решение. Настоящий ответ на обе проблемы — пункт 1.1, и его стоит запланировать сразу
следом. Как временная мера до 1.1: выставить для `saboteur2_world.png` и
`saboteur2_fg.png` режим импорта `Lossless` и снять галку VRAM-сжатия, чтобы хотя бы
не портить пиксель-арт.

**Критерий приёмки:** экспортировать desktop-сборку и запустить её — мир, передний план
и лифты отрисованы так же, как в редакторе. Проверяется тем же способом, что и в аудите:
проба на `ResourceLoader.exists()` внутри упакованной сборки.

### 0.3. Вернуть метаданные импорта в git (ревью 5.1, 5.2)

Файл: `.gitignore`.

Удалить строку `*.import`. Для Godot 4 эти файлы обязаны быть в репозитории: они хранят
UID и настройки импорта, и без них UID генерируются заново на каждой машине. Прямое
следствие уже видно в логе — `invalid UID: uid://bgiofmaad0ugq` в
`assets/tilesets/saboteur85_tileset.tres`.

Затем закоммитить всё, что должно было быть в git:

```bash
godot --headless --import          # сгенерировать .import и .uid
git add '*.import'
git add assets/shaders/zx_ink_outline.gdshader.uid scripts/world/lift.gd.uid
```

Правильный `.gitignore` для Godot 4 исключает только `.godot/` — всё остальное
(`.import`, `.uid`) версионируется.

Чтобы `.uid`-файлы не приходилось потом добавлять по одному вручную (как в коммите
«Track the Godot UID for the energy dial script»), достаточно один раз добавить их все
скопом после полного импорта.

**Критерий приёмки:** после `git clean -xdf && godot --headless --import` команда
`git status` показывает пустой diff, а предупреждение об invalid UID исчезло.

### 0.4. Починить CI (ревью 2.4, 2.5)

Файл: `.github/workflows/android-export.yml`.

Три независимые проблемы: workflow не запускается, экспорт не может пройти проверку
конфигурации, и падение экспорта не роняет job.

**Триггер.** Ветка по умолчанию — `master`, а workflow слушает `main`. Либо исправить
триггер, либо переименовать ветку; главное — сделать это осознанно, а не «на всякий
случай в обе».

**Конфигурация экспорта.** Проверено на этой машине, что нужно ровно две вещи:

- `--install-android-build-template` в связке с `--export-debug`. Флаг требуется, потому
  что `export_presets.cfg` содержит `gradle_build/use_gradle_build=true`, а `android/build/`
  в `.gitignore`. **[проверено]** — после добавления флага ошибка `Android build template
  not installed in the project` исчезает, а каталог `android/build/` создаётся.
- Пути к Android SDK и JDK, записанные в **editor settings**. **[проверено]** Godot 4.6
  **не читает** `ANDROID_HOME` и `ANDROID_SDK_ROOT`: с корректно выставленными
  переменными окружения экспорт всё равно падает с `Invalid Android SDK path in Editor
  Settings`. Работает только запись в `~/.config/godot/editor_settings-4.6.tres`.

Рабочий вариант шага (проверен до момента запуска Gradle):

```yaml
      - name: Configure Godot editor settings
        run: |
          mkdir -p ~/.config/godot
          cat > ~/.config/godot/editor_settings-4.6.tres <<EOF
          [gd_resource type="EditorSettings" format=3]

          [resource]
          export/android/android_sdk_path = "$ANDROID_SDK_ROOT"
          export/android/java_sdk_path = "$JAVA_HOME"
          EOF

      - name: Export debug APK
        run: |
          mkdir -p exports
          godot --headless --import
          godot --headless --path . \
            --install-android-build-template \
            --export-debug "Android" exports/saboteur92.apk
          test -s exports/saboteur92.apk
```

`godot --headless --import` отдельным шагом нужен потому, что при первом запуске импорт
идёт параллельно со сканированием файловой системы, и экспорт может стартовать раньше,
чем ассеты импортированы.

Финальный `test -s` — защита от главного, что здесь может пойти не так: сейчас
`upload-artifact` спокойно выложит пустой или отсутствующий APK, и CI будет зелёным при
сломанной сборке.

**Дополнительно стоит добавить в тот же workflow smoke-проверку**, которая ловила бы
класс ошибок из 0.1 и 0.2 автоматически:

```yaml
      - name: Smoke run
        run: |
          godot --headless --quit-after 300 2>&1 | tee run.log
          ! grep -q "ERROR:" run.log
```

Именно такой шаг поймал бы и `McpBridge`, и любую будущую поломку автозагрузок.

**Критерий приёмки:** workflow запускается на push в `master`, шаг экспорта завершается
успешно, артефакт содержит непустой APK.

## Этап 1 — мобильная пригодность

Проект называется мобильным ремейком, но на телефоне сейчас не запустится по памяти
и не пройдёт дальше первой лестницы по управлению.

### 1.1. Перевести карту на `TileMapLayer` (ревью 3.1)

Это самый выгодный по соотношению «эффект / трудоёмкость» пункт всего плана.

Мозаика уже является сеткой символьных ячеек 8×8 — `build_s2_world.py` именно так её и
разбирает (`CELL = 8`). Я посчитал, сколько среди них уникальных:

```
world png        : 8192 x 4608
ячеек всего      : 589 824
ячеек уникальных : 2 968
самая частая     : 174 330 повторений (29.6% карты)
```

То есть 590 тысяч ячеек карты складываются всего из 2968 различных картинок. Атлас
тайлсета получается **440×440 пикселей**, это **0.74 МБ** в RGBA8 вместо 144 МБ на
текстуру. С учётом переднего плана: **288 МБ → около 1.5 МБ, примерно в 190 раз меньше.**

Побочные выигрыши, которые тут не менее важны, чем память:

- Снимается вопрос с блочным сжатием из 0.2 — атлас такого размера можно держать
  Lossless без потерь качества и без последствий для памяти.
- Снимается риск упереться в `GL_MAX_TEXTURE_SIZE`: 8192 — это ровно предел у заметной
  части мобильных GPU, 440 — ни у кого.
- `TileMapLayer` рисует только видимые ячейки, а не текстуру на 37 мегапикселей целиком.
- Из репозитория уходят два больших бинарника, а вместе с ними — часть претензий по 5.1.

План работ:

1. Расширить `tools/saboteur_rip/build_s2_world.py`: он уже проходит по всем ячейкам —
   добавить сбор уникальных ячеек в словарь, выгрузку атласа
   `assets/tilesets/s2_world_tileset.png` и индексов ячеек в `s2_collision.json`
   (или в отдельный `s2_world_tiles.json`).
2. Собрать `TileSet` с размером тайла 8×8 из этого атласа.
3. В `level_01.gd` вместо `_add_map_sprite()` заполнять `TileMapLayer` через
   `set_cell()`. Кстати, узел `TileMapLayer` в `level_01.tscn` уже есть — сейчас он
   отключён в `_hide_demo_entities()`.
4. То же самое для переднего плана — отдельным слоем с своим `z_index`.

Коллизии при этом остаются как есть: 4643 прямоугольника из JSON работают и трогать
их незачем.

**Критерий приёмки:** карта визуально идентична текущей; `saboteur2_world.png` и
`saboteur2_fg.png` больше не грузятся в рантайме; APK запускается на реальном устройстве.

### 1.2. Достроить сенсорное управление (ревью 3.2)

Файл: `scenes/ui/touch_controls.tscn`.

Сейчас четыре кнопки: `◀`, `▶`, `JMP`, `HIT`. Нужны ещё две — `▲` (`move_up`)
и `▼` (`move_down`). Без них на телефоне **невозможно спуститься по лестнице, присесть
и опустить лифт**, при том что в мире 67 лестниц и 4 лифта.

После этого имеет смысл убрать костыль из `player.gd::_climb_axis()`, который трактует
удержание `jump` на лестнице как «вверх». Он был обходным решением ровно этой проблемы,
и с появлением настоящей кнопки только запутывает: сейчас прыжок на лестнице означает
одно, а вне лестницы другое.

Отдельно: включить `input_devices/pointing/emulate_touch_from_mouse=true` в
`project.godot`. Сейчас `TouchScreenButton` не реагируют на мышь, и сенсорное управление
нельзя проверить на десктопе вообще — только собрав APK.

Заодно стоит пересмотреть раскладку. Кнопки расставлены абсолютными координатами под
viewport 1280×720 (`btnJump` в точке `(1120, 588)`), и `JMP` целиком попадает в правую
чёрную полосу `LETTERBOX_PX = 160`. На экране с другим соотношением сторон это разъедется.
Надёжнее — якоря `Control` вместо абсолютных позиций.

**Критерий приёмки:** на устройстве проходится маршрут «спуститься по лестнице →
присесть → проехать на лифте вниз» без физической клавиатуры.

**Критерий приёмки:** после трёх смертей игра предлагает начать заново, и это работает
без перезапуска приложения.

## Этап 3 — качество кода

Ни один пункт этого этапа не влияет на поведение игры. Делать их до этапа 2 смысла нет:
рефакторить код, который предстоит переносить, — двойная работа.

### 3.1. Свести четыре probe-функции к одной (ревью 4.2)

Файл: `scripts/player/player.gd`.

`_ladder_overlaps()`, `_ladder_overlaps_at()`, `_ladder_at_world()` и `_ladder_probe()`
делают одно и то же с точностью до трансформа и формы. Каждая создаёт новый
`PhysicsShapeQueryParameters2D`, две из них — ещё и новый `RectangleShape2D`.

`_ladder_overlaps()` вызывается **каждый физический кадр**, то есть проект аллоцирует
объекты в горячем цикле. На мобильном GC это заметно.

Свести к одной функции, у которой `PhysicsShapeQueryParameters2D` и рабочий
`RectangleShape2D` лежат в полях класса и переиспользуются:

```gdscript
var _probe_shape := RectangleShape2D.new()
var _probe_query := PhysicsShapeQueryParameters2D.new()

func _ladder_hits(center: Vector2, size: Vector2) -> bool:
	_probe_shape.size = size
	_probe_query.shape = _probe_shape
	_probe_query.transform = Transform2D(0.0, center)
	_probe_query.collision_mask = ladder_detector.collision_mask
	_probe_query.collide_with_areas = true
	_probe_query.collide_with_bodies = false
	_probe_query.exclude = [get_rid()]
	return get_world_2d().direct_space_state.intersect_shape(_probe_query, 1).size() > 0
```

Делать это надо аккуратно и с ручной проверкой лазанья: логика лестниц — самая тонкая
часть проекта, и она работает.

## Этап 4 — инфраструктура и процесс

### 4.1. Подключить `gdlint` (ревью 5.7)

Сейчас линтера нет. Я прогнал `gdlint` (gdtoolkit) по `scripts/` — **48 замечаний**:

| Правило | Количество |
|---|---|
| `class-definitions-order` | 44 |
| `max-line-length` (>100) | 4 |

Все 48 — стилистические, ни одной логической ошибки. Это хороший результат: код
действительно написан аккуратно, и привести его в соответствие с линтером — разовая
механическая работа.

Основная масса приходится на порядок объявлений: gdtoolkit ожидает
`signals → enums → consts → exports → pubvars → prvvars → onready`, а в проекте `const`
идут после `@export var`. Варианта два — переставить объявления либо ослабить правило
в `.gdlintrc`. Я бы переставил: порядок из gdtoolkit совпадает с рекомендациями
официального style guide Godot.

Добавить в CI отдельным шагом:

```yaml
      - name: Lint GDScript
        run: |
          pip install gdtoolkit
          gdlint scripts/
```

### 4.2. Добавить тесты (ревью 5.7)

Сейчас единственный способ заметить регрессию — запустить игру и посмотреть глазами.

- Разбор `s2_collision.json` — что 4643 солида, 67 лестниц и 4 лифта построились.
- Smoke-тест из 0.4 — запуск без `ERROR` в логе.
- Автотест прохождения из 2.2 — самый ценный, когда появится.

Фреймворк: GUT (`addons/gut`), запускается headless и хорошо ложится в GitHub Actions.

## Этап 5 — юридический статус

### 5.1. Определиться с рипами и добавить лицензию (ревью 3.4)

Сейчас `.gitignore` содержит честное намерение:

```
# Original game rips — dev reference only, do not ship
assets/reference/
```

Но производная от рипов — `assets/world/saboteur2_world.png` и `saboteur2_fg.png` —
закоммичена и попадает в APK. То есть отгружается ровно то, что решено не отгружать,
только перекодированное. Это графика Saboteur II: Avenging Angel (Durell Software, 1987).

Для личного прототипа это не блокер. В момент публикации в любом сторе — блокер.
Решать нужно до того, как проект станет публичным, потому что переделка мира
задним числом обесценит всю работу по расстановке миссии из 2.1.

Варианты:

- **Перерисовать мир по мотивам**, сохранив планировку и геймплейную сетку, но не пиксели.
  Планировка и механика не охраняются так, как конкретная графика. Пункт 1.1 здесь
  кстати: после перехода на тайлсет перерисовывать нужно не мозаику на 37 мегапикселей,
  а 2968 ячеек 8×8, причём значительная часть из них — повторяющиеся элементы фона.
- **Оставить рип только локальным референсом**: генерировать карту у разработчика
  скриптом, не коммитить результат. Тогда публичный репозиторий чист, но собрать игру
  без исходных дампов нельзя.
- **Получить разрешение правообладателя.** Долго и неопределённо, но для ремейка
  культовой игры вариант рабочий.

Независимо от выбора — добавить `LICENSE` в корень. Сейчас `README` ограничивается
фразой «Game assets and code are part of the saboteur-92 project», которая не определяет
ничего: без явной лицензии код по умолчанию закрыт для любого использования.
Разумно развести условия: код под OSI-лицензией, ассеты — отдельным пунктом.
